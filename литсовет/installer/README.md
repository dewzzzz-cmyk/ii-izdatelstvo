# Установщик для Windows

Собирает архив, который пользователь распаковывает и ставит двойным щелчком.
Рассчитан на русскую Windows 10/11.

## Сборка

```bash
python installer/build-installer.py
python installer/zip-installer.py "%USERPROFILE%\Desktop\Литсовет-установщик.zip"
```

`build-installer.py` делает две вещи: вызывает `gen-installer.py` (тот пишет три
bat-файла) и собирает `installer/pkg/app/` — payload по **явному белому списку**
файлов. Белый список, а не «скопируй всё кроме»: чёрный список молча протаскивал
бы в дистрибутив папку `data/` с чужими книгами, логи и черновые скрипты.
Забытый нужный файл виден сразу — приложение не стартует; забытый лишний не
виден никогда.

После сборки скрипт проверяет все относительные `import` в скопированных
модулях и ссылки в `index.html`. Если файл из белого списка забыт, сборка падает
здесь, а не у пользователя в браузере.

## Что внутри архива

```
УСТАНОВИТЬ ЛИТСОВЕТ.bat     ← то, что запускает пользователь
app\                        ← сама программа
   Литсовет.bat             ← ярлык на рабочем столе будет указывать сюда
   УДАЛИТЬ ЛИТСОВЕТ.bat
   server.js, index.html, styles.css, src\, test\, data\
```

## Кодировка: почему CP866, а не UTF-8

`cmd.exe` читает bat-файл в **текущей кодовой странице консоли**, а у русской
Windows это 866. Файл в UTF-8 покажет кракозябры. Лечение через `chcp 65001` в
первой строке — известный источник других бед: ломается `pause`, ломаются
локализованные подсказки и разбор длинных строк.

В CP866 нет длинного тире, многоточия и кавычек-ёлочек. `gen-installer.py`
заменяет их на доступные аналоги, а потом **проверяет круг**: то, что прочтёт
`cmd.exe`, обязано посимвольно совпасть с исходником. Молча выбросить символ
нельзя — получится текст с дырками.

## Что установщик делает

Единственная точка входа в дистрибутиве — `УСТАНОВКА ЛИТСОВЕТА.bat` с меню:
«Установить / Обновить / Удалить / Выход». Раньше файлов было три (установить,
запустить, удалить), и два из трёх лежали внутри папки установки — то есть
были не видны сразу после распаковки архива.

1. **Установить** — проверяет Node.js ≥ 18 (при отсутствии предлагает поставить
   через `winget`), спрашивает папку (по умолчанию `%LOCALAPPDATA%\Litsovet`),
   копирует файлы, создаёт ярлыки на рабочем столе и в меню Пуск, проверяет,
   что ключевые файлы на месте.
2. **Обновить** — то же копирование поверх существующей установки; `data\`
   не трогается.
3. **Удалить** — делегирует в `УДАЛИТЬ ЛИТСОВЕТ.bat` внутри папки установки
   (одна копия опасного кода, а не две). Спрашивает слово «удалить», затем
   отдельно — удалять ли книги.

Установленный путь нигде не хранится (не в реестре, не файлом-маркером) —
меню находит его по ярлыку на рабочем столе или в Пуске при каждом запуске
`.bat`, а внутри одного запуска отслеживает сам, не спрашивая заново.

Запуск (`Литсовет.bat`) поднимает сервер на `HOST=127.0.0.1`, а не на всех
интерфейсах: не будет запроса брандмауэра, и книги не окажутся доступны соседям
по сети. Порт 8788. Повторный запуск не поднимает второй сервер — открывает
вкладку в браузере.

Удалить сам себя bat-файл не может (пока выполняется, файл открыт), поэтому
папку сносит отдельный отложенный процесс через 3 секунды; `server.js`
удаляется сразу же, синхронно — по нему меню сразу видит, что установки
больше нет, не дожидаясь отложенного шага.

### Задокументированная ловушка cmd.exe: PowerShell/COM внутри цикла меню

При автоматизированной проверке (кормление ответов через `<файл`, не с
клавиатуры) обнаружился воспроизводимый дефект: вызов PowerShell с
COM-объектом (`New-Object -ComObject WScript.Shell`) внутри цикла меню, ПЕРЕД
следующим `set /p`, иногда съедал часть входного потока — следующий вопрос
молча получал пустой ответ. `for /f 'command'` тоже способен целиком осушить
перенаправленный `stdin` (проверено воспроизводимо на `whoami`, `node -v` —
дело не в конкретной программе). Обходной путь применён: PowerShell с
COM-детектором ярлыка теперь вызывается **один раз** при старте скрипта, а не
при каждой отрисовке меню; путь установки дальше отслеживается локальной
переменной `%ЦЕЛЬ%`, обновляемой самим скриптом после установки/обновления/
удаления. Также заменены: `pause` → явный `set /p` (у `pause` под
перенаправлённым вводом непредсказуемое поведение чтения), `set /p X=<файл` →
`for /f "usebackq" ... in (файл) do set` (первое путает внутренний буфер
чтения cmd.exe). Этот класс проблем — свойство файлового тестового харнесса,
не реальной интерактивной консоли с клавиатурой; но обходы не помешают и
пользователю.

## Как проверялось

Прогон на этой машине (кодовая страница 866, локаль ru-RU), полный цикл:

- установка из распакованного архива в чистую папку — русский текст читается,
  ярлыки созданы, цель ярлыка существует;
- запуск: сервер слушает **только** `127.0.0.1:8788`, отдаёт `index.html`,
  `src/ui/app.js`, `styles.css`, а `/data/projects/` закрыт (403);
- повторный запуск: определяет работающий экземпляр и не поднимает второй;
- удаление, три ветки: отказ (ничего не тронуто), удаление программы с
  сохранением книг, полное удаление вместе с папкой.
