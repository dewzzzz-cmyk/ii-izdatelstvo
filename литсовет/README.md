# Литсовет

ИИ-инструмент для написания прозы: многоагентный пайплайн (Архитектор → Прозаик ⇄ Оценщик → Стражи → Линейный редактор) с авторским контролем, памятью канона и экспортом в EPUB/DOCX/MD.

## Запуск

**Windows:** дважды кликните `deploy.bat` (проверит Node.js, запустит сервер, откроет браузер).

**Linux/macOS:**
```bash
chmod +x start.sh
./start.sh
```

**Вручную:**
```bash
node server.js
```

Откроется `http://localhost:8788` (порт можно переопределить переменной `PORT`).

Требуется Node.js 18+, https://nodejs.org — зависимостей и сборки нет.

## Данные

Проекты хранятся в браузере (IndexedDB) + синхронизируются на диск в `data/projects/` для доступа с других устройств. API-ключ никогда не сохраняется на диск — только в памяти браузера на время сессии.

## Перенос на другой компьютер

Запустите `build-deploy.bat` — соберёт архив на рабочем столе. На новом компьютере распакуйте и запустите `deploy.bat`.

## Тесты

```bash
npm test
```

Встроенный `node --test`, ни одной зависимости. Покрыты разборщики ответов
модели и инварианты, которые уже ломались: `extractJSON`,
`parseDebateRevision`, `parseSceneSummary`, `looksTokenTruncated`,
`validateSkeleton`, `findGhostCharacters`, `lineEditMessages`,
`rememberRejected` и другие.

Отдельно есть стенд — проект с заранее заведёнными поломками, чтобы не
проверять их на живой книге:

```bash
node test/seed-stand.mjs http://localhost:8788
```

## Соглашение: сбой не сообщается через `null`

Больше половины багов этого проекта имели одну форму: функция возвращала
`null` при неудаче, а вызывающий принимал это за успех и шёл дальше. Наглядный
случай — сцена помечалась «Готово» без сводки в памяти, и следующие сцены
писались вслепую к её событиям.

Правило для нового кода:

- функция, которая может не справиться, **бросает исключение** (как
  `proofreadText` при отсутствии ключа) либо возвращает `{ ok:false, reason }`;
- если `null` всё же используется как «не получилось» (так устроены
  разборщики: `extractJSON`, `parseSceneSummary`, `parseEvaluator`), то
  **каждый** вызывающий обязан его проверить и сказать автору, что именно не
  вышло и чем это грозит. `try { await f() } catch {}` вокруг такой функции —
  не защита: `null` не бросает, и `catch` не сработает никогда.
